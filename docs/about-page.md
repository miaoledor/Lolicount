# How / About 页面

`/about` 仅介绍项目和使用方法：简短项目介绍、主题统计、三步操作说明，以及可复制的 Markdown 示例。
页面不再展示个人头像、节拍器、技术栈、社交卡片、求 Star 卡片或页脚导航。

## 两项主题统计

数据直接来自现有 `GET /api/themes`，与 Playground 的可选主题保持同一口径：

- **主题总数**：接口返回列表的长度，包含静态与 PSB / Spine / Live2D / Unity 动态主题。
- **单个主题最多变化数**：所有有效 `variants` 的最大值，而非所有主题变化数之和。
  对应主题名可点击，跳转至 `/?theme=主题名`，在 Playground 中直接选中。

没有提供 `variants` 的主题会计入主题总数，但不会被推断为拥有某个变化数。
空主题库显示总数 `0`，未知的最大变化数显示 `—`。请求期间显示占位；请求失败显示提示和重试按钮，
不把加载失败伪装成 `0` 个主题。数字随当前主题库变化，不写死在文案或测试中。

Nuxt 静态构建不依赖后端在线。页面挂载后读取接口；统计不会生成新访问记录。
沿用现有 API 契约，无后端 API、缓存、限流、存储或数据库 schema 改动，**无需数据库迁移**。

## 使用说明

1. 在 Playground 选择主题，输入专属计数器名称；相同名称共用计数。
2. 调整外观并点击生成，检查预览。
3. 复制生成的 Markdown、图片链接或图片标签，贴入 README / 博客 / 网站。

页面提供可复制的 Markdown 示例，并提示替换 `your-name`。
示例域名优先使用运行时 `/api/config` 返回的公开域名，其次使用构建配置或当前站点。
需要播放器的动态主题提示使用 Playground 提供的挂件 HTML。

## 验证

```sh
pnpm test:about
pnpm --dir web generate
```

将生成的 `web/.output/public/` 内容复制到 `assets/dist/` 后运行：

```sh
go test -race -count=1 -p 1 ./internal/server -run 'TestFrontend|TestHomeIsPlayground|TestAPIThemesList'
```

单元测试使用独立的小型与大规模模拟集合，覆盖混合主题、空集合、未知变化数、无效数值、
并列最大值、精度边界和多语言完整性。Go 回归校验 `/about` 与 `/about/` 独立页面、
统计占位、三步说明、旧模块移除及 HTML 缓存策略，不依赖主题数量或名称。

人工检验：运行 `pnpm dev` 后访问 `http://localhost:3721/about`；对比 `/api/themes` 的条目数
及 `variants` 最大值，点击最大变化主题名验证选中状态，复制示例并粘贴检查。
切换中英日文和深浅模式，并在 320px、390px 与桌面宽度检查数字、说明和示例是否完整显示。
后端不可用时刷新，应显示统计不可用与重试，使用说明仍可阅读。
